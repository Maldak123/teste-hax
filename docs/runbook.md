# Operação

- **Recaptcha ou token expirado:** resolva a recaptcha na janela aberta por `npm run room` ou obtenha token novo pela página oficial, atualize `ROOM_TOKEN` no ambiente e reinicie o comando. Não automatize a resolução de recaptcha.
- **Sala desconectada:** confira a página Headless e a conectividade WebRTC. Reinicie `npm run room`; partidas iniciadas sem finalização aparecem em `interruptedMatches` no próximo boot do serviço.
- **Automação do Chrome:** no WSL, o Chrome do Windows é controlado pelo PowerShell no Windows com porta livre e perfil temporário. Se `CHROME_DEBUG_PORT` foi definido e está ocupado, remova-o ou escolha outra porta. Se o navegador não for encontrado, configure `CHROME_PATH`. Aguarde a mensagem `Página Headless aberta` antes da recaptcha. Se só aparecer `about:blank`, encerre a tentativa antiga e confira o erro no terminal. `CHROME_PROFILE_DIR` permite um perfil Windows exclusivo; o Chrome exige um perfil não padrão para depuração remota. Mantenha a porta DevTools acessível somente localmente.
- **Disco cheio ou replay nulo:** preserve `data/state.json`, libere espaço e examine `replayStatus`. Replays nulos não podem ser reconstruídos. Não altere um arquivo de replay manualmente sem atualizar seu checksum.
- **Discord indisponível:** `pending` retorna automaticamente após HTTP 429. `uncertain` exige conferência do canal para evitar duplicata; `failed` exige corrigir configuração ou permissão. Com o processo parado, faça backup de `state.json` antes de qualquer reconciliação manual.
- **Resultado pendente:** procure `persist_match_failed` no console da página Headless. `status: "rede"` indica que a chamada não chegou ao serviço; confira `http://127.0.0.1:8787/health` (ou a porta configurada) no mesmo navegador e mantenha a página aberta. Status 422 indica registro rejeitado; confira o `request_error` do serviço. O bot libera o lobby e tenta salvar novamente a cada cinco segundos. Não feche a página até a pendência ser enviada; a fila do navegador ainda não é durável.
- **Segredos e privacidade:** mantenha `.env` e `data/` legíveis só pelo operador. Para exportar dados de um jogador, localize seu `playerId` em `state.json` e entregue apenas as entradas relevantes após confirmar a identidade. Para exclusão, faça backup, pare o serviço, remova a identidade e os dados relacionados do arquivo e dos replays afetados conforme a política local, e registre a operação. Replays podem conter outros participantes; avalie a exclusão com cuidado.

O serviço liga apenas em `127.0.0.1`; execute navegador e serviço na mesma máquina. Verifique estado da outbox e espaço em disco regularmente. Faça backup com o serviço parado. O formato JSON atende uma única instância de sala.
